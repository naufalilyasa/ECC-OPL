# WI-20261128-002-uww-functional-closure-v1-1 — Functional closure v1.1

deliveryStatus: COMPLETED_WITH_LIMITATIONS
verificationStatus: PARTIAL

## Summary

The work-item helper's resolution and lifecycle semantics were rewritten so a task binds to its own
identity instead of whatever node was active last. The `plan-prd` command is projected into OpenCode
again, the event/progress schema carries run, revision, outcome and evidence, and consumer Git
hygiene is now verified against real `git status` in disposable repositories. Two items from the v1.1
spec are not closed: no framework-native Canvas session exists on this machine, and the end-to-end
acceptance chain stops at the owner approval gate.

## Objective

Close the v1.1 "Functional Closure" gaps: default workspace binding, helper lifecycle correctness,
structured progress, PRD registration and routing, Git ignore hygiene, and a coherent WI-002 report.

## Decisions

- `bind` replaces `ensure` as the honest name (`ensure` stays as an alias so existing callers keep
  working). Resolution is: explicit id → exact slug match → new item. The last active pointer is
  never used as a substitute for task identity.
- An unknown explicit id fails with exit 1 in both `resolve` and `bind`. Printing `none` with exit 0
  let a preamble mistake a failed resolution for a successful binding.
- `bind --id` reopens a closed item instead of leaving it `closed` while bound, and `reopen` exists
  as an explicit command.
- `archive` only accepts a closed item (unless `--force`), scans `archive/` when minting a new id, and
  records external artifact references in `archive/index.json` so the reference survives the move.
- Only `reports/` stays trackable. Manifests were dropped from the tracked surface because progress
  and timelines are derived and would otherwise create review noise.
- The consumer ignore file is generated by `bind`, never by a new install step: `.ecc-opl/.gitignore`
  by default, `.git/info/exclude` with `--ignore-mode local`, nothing with `--ignore-mode none`.
- No PRD was authored for this corrective work. `plan-prd` registers requirements for product work;
  inventing a PRD to satisfy an acceptance checklist would be fabricated evidence.

## Corrected binding and lifecycle behavior

| Before | After |
|---|---|
| `ensure --slug unrelated-feature-b` returned feature-a's id | exact slug match resumes, different slug creates a new item |
| `resolve --id UNKNOWN` printed `none`, exit 0 | exit 1, `unknown work item` on stderr |
| Rebinding a closed item left `status: closed` | `bind --id` reopens it; `reopen` is explicit |
| `nextId` scanned only `work-items/` | scans `work-items/` and `archive/`; archived ids are not reused |
| `archive` accepted an active item | refuses unless closed or `--force` |
| `append` accepted any free-text outcome | outcome is one of `pass|fail|blocked|pending_approval|skipped|incomplete` |
| `progress` counted events only | carries `runs`, `revisions`, `outcomes`, `blockers`, `pendingApprovals`, `nextActions` |
| work-item preambles fell back to standalone when no pointer existed | they bind `TASK_SLUG`; legacy paths only under `--standalone` or `ECC_OPL_STANDALONE=1` |

`progress.json` is still a pure rebuild from `timeline.jsonl`: nothing is inferred from artifact
existence or event count, and a later run appends rather than overwriting earlier evidence.

## PRD registration and routing

- `commands/plan-prd.md` remains the canonical producer; `.opencode/commands/plan-prd.md` is restored
  as its OpenCode projection, writing into `.ecc-opl/work-items/<ITEM>/prd/` when bound.
- `/plan` consumes only an `APPROVED` PRD from the bound item's `prd/` directory (or a draft the owner
  names explicitly); `/tdd` consumes only the approved plan for that item.
- AGY projection check: `ecc install --target antigravity --profile full --dry-run` emits
  `commands/plan-prd.md → .agents/workflows/plan-prd.md`.
- OpenCode projection check: `ecc install --target opencode --profile full --dry-run` emits
  `.opencode/commands/plan-prd.md → ~/.config/opencode/commands/plan-prd.md`.

## Limitations

- The acceptance chain `plan-prd → plan → owner approval → tdd → code-review-quick → refactor-clean →
  e2e → update-docs` was not run end to end. It is recorded as `pending_approval` on the plan event;
  completing it requires the owner's approval, which is not something this run can produce.
- No framework-native Canvas session was opened. cc-reminder's pilot remains `standalone-html`; the
  Vue and React/Next adapters have still never executed live.
- `~/.config/opencode/commands/plan.md` is a diverged user-modified copy that ECC no longer manages,
  so a consumer project without its own `.opencode/commands/` resolves the older command body. Only
  projects carrying the project-local commands (or fresh installs) get the new binding.
- The local Guardian Angel hook intermittently refuses to execute
  `tests/scripts/work-item.test.js` because the suite creates a throwaway `.git/info`. The 17/0 run
  above used an identical copy at another path.
- Structure parity for the cc-reminder sections stays structural (element/class tree and CSS rules),
  not pixel-wise; no screenshot diff exists.
